## 6. PDF progress bar (Phase 4)
Root causes found and fixed:
1. The overlay swapped from the simulated curve (eased to 40%) to the first *measured* byte percent (often ~8%) → visible backwards jump. The simulated curve is now frozen the moment real bytes arrive and the shown value is the max of both, so it only climbs.
2. Internal retries (range-stall → whole-file byte fallback, transport retry) remounted the overlay and reset it to 0%. New `src/lib/readerProgressStore.ts` keeps a monotonic per-document floor that survives remounts and clears on ready / on a different document.
3. The whole-file fallback only emitted an indeterminate heartbeat, so the bar looked frozen for the whole download. It now streams the response and reports real `content-length`-based percentages; the label reads "Reconnecting" while indeterminate.
- Covered by `src/test/readerProgressStore.test.ts` (5 tests) plus the updated fit tests.

## 7. Razorpay + enrollment security
- `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET` replaced with test-mode values (entered by you in the secure form) and all payment functions redeployed: `create-razorpay-order`, `create-subscription-order`, `verify-razorpay-payment`, `verify-subscription-payment`, `razorpay-webhook`, `razorpay-refund-webhook`, `initiate-refund`.
- New admin-only `payments-health` function reports key mode (`test` / `live`), whether the id+secret pair actually authenticates against Razorpay, and whether the webhook secret is set — never the key itself. Unauthenticated call returns `401` (verified).
- **Bypass hole closed:** `enrollments` had two client INSERT policies; because policies OR together, a student could insert an enrollment row directly for any zero-priced course, skipping the `self-enroll-free` checks (course must be active, rate limit). Both policies dropped; a new admin-only INSERT policy keeps the admin enrollment manager working. Remaining policies: student read own, student update own progress, admin manage.
- Enrollment writes now flow only through server code: `self-enroll-free` (price 0 + active + rate limited), `verify-razorpay-payment` (HMAC signature, order scoped to user+course, amount re-fetched from Razorpay, `captured` required, refunds rejected, idempotent replay, atomic RPC), `razorpay-webhook` fallback, admin tools.
- Existing trigger still blocks tampering with `status`, `user_id`, `course_id`, `purchased_at`.
